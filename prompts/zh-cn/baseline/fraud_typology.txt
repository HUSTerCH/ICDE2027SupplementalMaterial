# Goal
阅读上述案情描述，提取诈骗案件分类类型并映射到以下二级标签体系中，针对复合型诈骗，输出多标签以完整还原杀伤链。
# Processing Logic
1. 通读案情描述，忽略受害人的情绪化表达，精准判断骗子如何接触受害人和最终以什么名义让受害人掏钱
2. 严格根据以下标签字典，为案件匹配分类标签。请同时输出 L1 和 L2 标签,按照<L1><L2>的格式输出：
    - 身份冒充类：<L1_Identity> ，冒充具有公信力或熟人关系的身份，滥用信任实施诈骗
      * 公检法及政府机关：<L2_Id_Gov>，冒充公安、检察院、法院及银保监会、征信中心等公权力监管/清算机构，含冒充其人员或伪造其载体（文件/官网/APP/公众号/官方短信等）
      * 领导/熟人/公众人物/商业伙伴：<L2_Id_Acquaintance> ，冒充亲友、同事、领导、明星等熟人身份，或在商业场景中冒充供应商、客户、企事业单位等已有或潜在的商业合作伙伴
      * 平台/客服：<L2_Id_Service> ，冒充电商、物流、金融、互联网平台等官方客服
      * 军警等特殊身份：<L2_Id_Military> ，冒充军队、警察、消防等采购人员
    - 金融信贷类：<L1_Finance> ，利用资金需求、增值期望或止损心理实施诈骗
      * 虚假贷款与信用卡：<L2_Fin_Loan> ，以低门槛贷款为诱饵，诱导受害人
      * 虚假征信修复：<L2_Fin_CreditFix> ，以影响征信、注销贷款账户、注销校园贷等为由，诱导受害人操作
      * 虚假投资理财：<L2_Fin_Invest> ，以高回报为饵，引导下载虚假投资平台，大额投入后无法提现或亏损
      * 虚假资金清退与退款：<L2_Fin_Recovery> ，针对曾受骗或投资亏损等人群，以清退、回款为名行骗
    - 诱饵类/机会欺诈：<L1_Bait> ，捏造低成本高收益的虚假机会
      * 刷单与任务返利：<L2_Bait_Task> ，以点赞、刷单、做任务赚佣金为名，前期小额返利，后期以如连单、解冻等理由要求持续转账
      * 虚假招聘/兼职：<L2_Bait_Job> ，以高薪兼职、手工活、日结、招工等虚假就业信息作为引流入口或收割手段
      * 网络赌博与虚假福利中奖：<L2_Bait_GambleAndLottery> ，以发现博彩漏洞/有平台内部消息/能稳赚不赔为诱饵，诱导参与网络赌博，或以虚假发放福利/中大奖需缴纳税费、保证金等为由，诱导受害人转账
    - 交易类：<L1_Transactions> ，建立在具体虚假商品/服务上的契约破坏
      * 网络游戏虚假交易：<L2_Tran_Game> ，以买卖游戏账号、装备、皮肤等虚拟商品为名，引导至外部假平台
      * 虚假购物与服务：<L2_Tran_Shop> ，围绕二手商品、票务、代购、生活服务等交易履约环节，骗子以买家或卖家身份接触受害人，适用于C2C场景，受害人既可以是买家也可以是个人卖家
      * B2B欺诈/虚假采购 - 卖家被骗：<L2_Tran_Procurement> ，冒充大客户或企事业单位，向商户（如饭店、建材商、企业等）下达大额虚假订单，并诱骗商户垫付货款或定金等，仅适用于B2B商业场景
    - 长线社交与色情引流：<L1_Social> ，利用情感或生理欲望建立信任后收割
      * 网络婚恋交友/杀猪盘：<L2_Soc_Romance> ，长线网恋/交友建立信任，随后诱导投资、转账、代操作账户或引流到其他骗局
      * 重金求子及色情引流：<L2_Soc_Sex> ，以提供各类色情服务为诱饵，诱导受害人进入骗局以逐步收割
    - 网络黑灰产与敲诈勒索：<L1_Illegal> ，技术性盗刷或施加恐吓与社会性死亡威胁强制收割
      * 胁迫与敲诈勒索：<L2_Ill_Extortion> ，针对名誉受损、职场危机、数据灭失或性丑闻曝光的“绝对恐惧与极度应激”。与各类引流的主动消费完全不同，此为单向的强制性收割
      * 账号劫持与技术盗刷：<L2_Ill_ATO> ，通过木马、伪基站、屏幕共享窃密、骗密码异地登录等手段，在受害人非主动授权情况下盗转资金
3. 易错场景防偏离：
    - 身份冒充类提取铁律：身份冒充类的核心是明确存在冒充情节，且冒充普通公民默认信任的身份，如公权力机构、熟人、明星偶像、已经或正在谈合作的商业客户/供应商、有大厂/银行背书的平台/客服、自带身份光环的军警消防等，核心目的是获取受害人的社交信任；若嫌疑人捏造身份不是为了获取社交信任，而是为了合理化诈骗话术，如捏造大客户身份合理化自己的虚假大订单，则不归为身份冒充
    - 冒充熟人/商业伙伴的归类：无论冒充的是私人熟人（亲友、同事、领导）还是商业合作伙伴（供应商、客户、企事业单位对接人），只要目的是滥用受害人对该身份的既有信任，均统一归入<L2_Id_Acquaintance>
    - <L2_Id_Gov> 载体伪造 vs 口头背书：伪造上述机关载体（文件/官网/APP/公众号/官方短信等）即打，不论目的；仅口头援引机关名义施压或收款（如"会被银监会冻结""转银监会账户"）而未伪造载体，不打
    - <L2_Tran_Shop> vs <L2_Tran_Procurement>：受害人若是个人消费者或二手物品转卖者，因想购物或购买服务（均为虚假的）或出售闲置时被骗，属于前者；受害人若是经营实体，被冒充的大客户骗，则属于后者。B2B虚假采购场景中，若诈骗者的身份伴随持续性信任建立行为，如提供证照/名片/合同，或双方本有业务往来，需同时输出<L2_Id_Acquaintance>；若仅为临时捏造的虚假大客户身份，不叠加身份冒充标签。所有涉及网络游戏虚拟商品的交易诈骗，无论受害人是买家还是卖家，均优先归入<L2_Tran_Game>
    - 刷单链内收割不升级金融标签：刷单返利类诈骗中，所有以“操作错误、账户冻结、连单卡单、流水不足”等为由要求继续转账的行为，均属于 <L2_Bait_Task> 固有组成部分，不可升级为金融相关标签。只有当骗子引导受害人脱离原刷单平台，进入一个全新独立的投资平台并实施理财类诈骗时，才考虑叠加金融标签
    - 虚假资金清退/退款的严格界定：<L2_Fin_Recovery> 适用于曾经真实遭受资金损失的人群（如P2P暴雷、网课/健身房倒闭、过往投资亏损等，案情描述中存在清退、退费等字眼）进行的二次诈骗，消费者因物流/商品质量问题被冒充客服以理赔为由骗的不得使用本标签
    - 社交工程与技术盗刷的区分：
        * 不属于：若资金划转是由受害人自行完成（主动扫码、输入金额/密码），或受害人主动将用于单次转账的验证码暴露给骗子，属于社交工程诱导的主动授权，不打该标签
        * 属于：必须是骗子获取了底层控制权并在受害人非主动授权下独立完成转账。包括：1. 底座接管：骗取 Apple ID、网银账号密码，或骗取用于“登录金融APP/重置密码/绑定数字钱包”的验证码后，骗子异地登录接管账户；2. 远控/共享窃密：通过屏幕共享的视野盲区窥视截获验证码/密码，或直接远控鼠标转账；3. 硬技术攻破：利用木马病毒等静默拦截短信或操控设备
        * 简单区分：骗子在受害人不继续给验证码的情况下，能继续盗刷资金，则属于，反之则不属于
    - 婚恋交友与色情引流的区分：<L2_Soc_Sex>侧重短平快的生理欲望，即使案情被美化为“同城交友”，凡呈现极短周期内（如当日）线下见面，均判定为色情引流；<L2_Soc_Romance> 侧重长线情感养成，依赖长期陪伴建立信任
4. 输出规范:
    - 必须且只输出一个合法的 JSON 格式数据，必须且只能包含两个字段：reason（分析案情演变过程）和labels，reason 字段必须在 labels 字段之前。
    - labels 中，使用级联的方式拼接L1和L2标签，如果同一个L1标签下有多个L2标签，拆分为两个元素。如："labels":["<L1_xxx><L2_yyy>","<L1_xxx><L2_zzz>","<L1_aaa><L2_bbb>"]
